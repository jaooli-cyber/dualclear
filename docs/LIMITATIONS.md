# Limitations

DualClear is deliberately narrow. These limitations are part of the supported
claim, not hidden implementation details.

1. **Maximum 16 bids.** The current fixed bound keeps execution and test vectors
   reviewable.
2. **Trusted ID assignment.** Lower IDs resolve exact remainder ties. IDs must
   be assigned by the venue, not strategically selected by bidders.
3. **Post-decode EVM bound.** The typed `DynArray` is materialized by ABI
   decoding before the adapter checks its length.
4. **Two error surfaces.** Native callers receive typed `InputError` values
   through `clear_native`/`clear_checked`. The assertion-based `clear`
   entrypoint remains for the enforcing EVM path and traps/reverts on invalid
   input.
5. **Non-cryptographic fingerprint.** FNV-1a64 detects ordinary integration
   drift; it is not collision-resistant.
6. **No settlement layer.** The kernel calculates allocations but does not move
   assets, authenticate orders, or enforce an auction schedule.
7. **Six-decimal price scale.** Prices use `UFixed<6>`; integrations must
   normalize external price units explicitly.
8. **Prototype status.** Fe 26.x and its native backend are evolving. Pin the
   exact compiler, rerun both target suites, and assess the final deployment
   environment.
9. **Outcome is a mutable snapshot.** `fills`, `canonical_bytes`, and
   `fingerprint` are consistent when returned by the kernel. Prototype callers
   must treat them as immutable; mutating one field later does not recompute the
   others.
10. **Host argument boundary.** The native CLI uses Fe 26.5's `argc/argv`
    bridge. The host locates each NUL terminator before the parser's 20/78-digit
    limits apply. Operating-system argument limits bound this, but the CLI is
    not an unbounded remote service.
11. **Buffered native output.** Fe 26.5's native host API does not expose a
    fallible final flush. A late write failure may therefore leave incomplete
    output even when `main` returned zero. Consumers must validate the complete
    DCG1 line and their own transport; DualClear does not promise an exit code
    for this host-runtime condition.
12. **EVM target compatibility.** The pinned compiler emits metadata with
    `evmVersion=osaka`. Integrators must verify that the destination chain
    supports the generated bytecode; reproducible compilation alone is not a
    universal-chain compatibility claim.
13. **No individual supply monotonicity.** Largest remainder can reduce an
    individual bid's fill when total supply increases between separate clears.
    Integrators must not assume house monotonicity.
14. **Per-bid, not participant-level fairness.** Deterministic venue IDs do not
    prevent a participant from splitting demand across several bids. A venue
    requiring participant-level fairness must authenticate and aggregate or
    limit equivalent orders by identity and price. See the
    [documented counterexamples](METAMORPHIC.md#explicit-non-properties).
